# Lily Ngo — Engineering Showcase

Selected code, technical walkthroughs, and process notes from projects in **game development, simulation, and software engineering**.

I'm a software engineer and technical lead who enjoys designing systems, building interactive experiences, and exploring how thoughtful engineering can support creative ideas. This repository focuses on the **implementation** behind my work: the problems I tackled, the decisions I made, and the code that brings them together.

The projects include both independent and team efforts, with my contributions identified in each walkthrough.

For my background, professional work, and full project portfolio, visit **[lily-ngo.com](https://lily-ngo.com)**.

## Featured projects

### [Fortune's Feast](https://github.com/lilynngo/Lily-Ngo-Showcase/tree/main/fortunes-feast)

**Godot · GDScript · Character systems · Technical art · UI programming**

A narrative deduction game where players investigate a royal court's preferences and relationships to plan a three-course banquet. Working with **Sleepy Puppy Studios**, I contributed art direction, character and environment art, technical art, and programming. This showcase highlights the character-interaction architecture I developed and the standalone Godot Technical Demo I built to validate artwork and environments before final production.

**Explore:** [Play the game](https://sleepypuppystudios.itch.io/fortunes-feast) · [Character systems](./fortunes-feast/docs/character-interaction.md) · [Selected GDScript](https://github.com/lilynngo/Lily-Ngo-Showcase/tree/main/fortunes-feast/src/character-system) · [Art-to-engine pipeline](./fortunes-feast/docs/art-to-engine-pipeline.md)

### [Chess with Points Simulator](https://github.com/lilynngo/Lily-Ngo-Showcase/tree/main/chess-with-points-simulator)

**Python · Game rules · Parallel simulation · Statistical modeling**

A two-week game-design assignment that became a simulation framework for evaluating the point costs of custom chess pieces. I implemented configurable piece behavior, automated matchups, and analysis that turns game outcomes into balance recommendations.

**Explore:** [Rules and simulation code](https://github.com/lilynngo/Lily-Ngo-Showcase/tree/main/chess-with-points-simulator/src) · [Project walkthrough](./chess-with-points-simulator/README.md)

### [Lock In Gamers: Mafia Adventure](https://github.com/lilynngo/Lily-Ngo-Showcase/tree/main/lock-in-gamers-mafia-adventure)

**Godot · GDScript · Gameplay systems · State management**

A single-player exploration game in which players discover and capture creatures, collect clues and rewards, and unlock new areas. As the sole programmer, I implemented the interactions connecting creature behavior, animation, collectibles, progression, and saved game state.

**Explore:** [Play the game](https://hacstudios.itch.io/lock-in-gamers-mafia-adventure) · [Curated source code](https://github.com/lilynngo/Lily-Ngo-Showcase/tree/main/lock-in-gamers-mafia-adventure/src) · [Gameplay architecture](./lock-in-gamers-mafia-adventure/docs/architecture.md)

### [Light the Way](https://github.com/lilynngo/Lily-Ngo-Showcase/tree/main/light-the-way)

**Ren'Py · Python · Progression systems · Unlockable galleries · Developer enablement**

A branching visual novel developed with **Simporiem Studios**. As lead programmer, I implemented shared progression, achievement, gallery, and UI systems across multiple story routes. I also created example scripts and recorded demonstrations to help teammates integrate features, while supporting GitHub onboarding, pull requests, and code reviews.

**Explore:** [Play the game](https://simporiem-studios.itch.io/light-the-way) · [Progression & gallery architecture](./light-the-way/docs/progression-and-gallery.md) · [Developer enablement](./light-the-way/docs/developer-enablement.md) · [Curated Ren'Py code](https://github.com/lilynngo/Lily-Ngo-Showcase/tree/main/light-the-way/code)

## About the code

This is a **curated engineering showcase**, not a collection of complete game source releases. Some projects include runnable examples; others include selected scripts and architecture explanations because their full games rely on separate assets, dependencies, or third-party content. Each project README explains its scope and distinguishes my work from team contributions.

The goal is to make the work easy to explore without requiring readers to dig through an entire development repository.
