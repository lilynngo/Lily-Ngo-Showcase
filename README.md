# Lily Ngo — Engineering Showcase

Selected code and technical walkthroughs from my independent projects in **game development, simulation, and software engineering**.

I'm a software engineer and technical lead who enjoys designing systems, building interactive experiences, and exploring how thoughtful engineering can support creative ideas. This repository focuses on the **implementation** behind my projects: the problems I tackled, the decisions I made, and the code that brings them together.

For my background, professional work, and full project portfolio, visit **[lily-ngo.com](https://lily-ngo.com)**.

## Featured projects

### [Chess with Points Simulator](./chess-with-points-simulator/)

**Python · Game rules · Parallel simulation · Statistical modeling**

A two-week game-design assignment that became a simulation framework for evaluating the point costs of custom chess pieces. I implemented configurable piece behavior, automated matchups, and analysis that turns game outcomes into balance recommendations.

**Explore:** [Rules and simulation code](./chess-with-points-simulator/src/) · [Project walkthrough](./chess-with-points-simulator/README.md)

### [Lock In Gamers: Mafia Adventure](./lock-in-gamers-mafia-adventure/)

**Godot · GDScript · Gameplay systems · State management**

A single-player exploration game in which players discover and capture creatures, collect clues and rewards, and unlock new areas. As the sole programmer, I implemented the interactions connecting creature behavior, animation, collectibles, progression, and saved game state.

**Explore:** [Curated source code](./lock-in-gamers-mafia-adventure/source/) · [Gameplay architecture](./lock-in-gamers-mafia-adventure/docs/architecture.md)

## About the code

This is a **curated engineering showcase**, not a collection of complete game releases. Some projects include runnable examples; others include selected scripts and architecture explanations because their full games rely on separate assets, dependencies, or third-party content. Each project README explains its scope.

The goal is to make the work easy to explore without requiring readers to dig through an entire development repository.
